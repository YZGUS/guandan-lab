## 必须修复的问题

### P1：局域网 HTTP 无法手动出牌或不要

通过 `http://192.168.31.96:8790/` 建房开局后，提示正常、出牌按钮可点击，但点击“出牌”或“不要”均捕获：

```text
Uncaught TypeError: crypto.randomUUID is not a function
```

该页面 `isSecureContext=false`，`crypto.randomUUID` 为 undefined。相同代码在 localhost 和 HTTPS 下正常。定位：`apps/web/src/GameTable.tsx:52` 与 `:61`。动作尚未发送，手牌保持27张。不能把超时托管随后出牌误认为手动操作成功。

### P1：最高三连对和钢板漏判

级牌7时，`Q♠ Q♥ K♠ K♥ A♠ A♥` 应为三连对，`K♠ K♥ K♦ A♠ A♥ A♦` 应为钢板，当前均返回 null。

定位：`packages/core/src/rules.ts:6`、`:7`。连续窗口枚举各少最后一个窗口，合法动作生成也受影响。

### P1：百搭的生成、识别和 Web 提示不一致

固定牌例：当前打10，手牌为 `5♠ 6♥ 7♣ 8♦ ♥10`，目标是普通顺子 `45678`。

合法动作生成器给出以9结尾的 `56789`，但牌型识别仅返回首次匹配的以8结尾的 `45678`。Web 提示只保留牌张ID，再次按默认方式识别，所以用户点提示后五张牌全被选中，出牌按钮依然禁用。

在独立测试服务构造该边界牌例，真实 React 牌桌复现并截图：`.data/web-acceptance/wild-hint-blocked.png`。

另一个固定例：seed=1、级牌7、0号位的 `1-H-3 1-S-4 1-S-5 1-H-6 2-H-7`，生成器声明 STRAIGHT/7，但校验器拒绝这个声明。定位：`packages/core/src/rules.ts:79`（首次匹配即return）；`apps/web/src/GameTable.tsx:29`、`:64`。

服务端定时器执行Bot动作出错后只清除计时器（`apps/server/src/game-server.ts`），因此此类不一致还有造成对局停住的风险；本轮未把风险推断称为已复现的随机Bot死局。

### P1：未实际打 A 时也可能直接判整场获胜

构造状态：南北队等级A，但本副打东西队的5；南北队包揽头游和二游。当前直接进入 MATCH_FINISHED。

按照“必须打A并通过”的口径，本副应先结算，由赢家下一副实际打A。定位：`packages/core/src/engine.ts:101`，只检查赢家已记录的等级，没有检查本副级牌。

### P2 / 规则口径缺口：双贡同点按牌ID决定先手

固定 seed=1、上一副顺序 `[2,0,1,3]`、下一副打5，两张贡牌同为5。当前选择1号位先手；按调研采用的“头游下家先手”应是3号位。

定位：`packages/core/src/engine.ts:218`、`:227`。同点时排序继续使用实体ID。项目 RULES 尚未写明同点细则，修复前应明确并记录这一产品规则。

### P2：小屏横屏裁切手牌

667×375、26张手牌时，实测6张牌越出牌桌区。固定牌宽、固定负间距和 `flex: 0 0 auto` 使牌列无法适应剩余宽度，`overflow:hidden` 隐藏了溢出，因此“document没有横向滚动”不足以证明手牌完整可见。

### P2：整场流程缺少返回入口

开始牌局后，Web牌桌没有离桌/解散入口。MATCH_FINISHED遮罩也没有返回大厅或再来一局按钮；刷新会恢复同一房间。服务端已有解散消息，但正常用户没有对应入口，完整用户流程不能闭合。

## 通过的规则场景

发牌与实体ID、单张/对子/三张/三带二、一般顺子、A低位与高位顺子、一般三连对与钢板、同花顺、四王炸、带王对子三带二、红桃级牌百搭、禁止六张顺子/绕接/两连对/混合大小王对子/百搭配王、炸弹层级与同点不可互压、领出不可过牌、非本人牌与重复实体牌拒绝、接风、有人出完后的剩余玩家过牌计数、3/2/1升级、实际打A时的头三获胜与头末不过A。

30个新副牌样本检查了贡还牌后108张实体牌唯一且四家各27张，观测到39次进贡和3次抗贡；这不是所有贡还细则的穷举证明。贡还仍为自动策略，人工选贡还交互尚未实现。
